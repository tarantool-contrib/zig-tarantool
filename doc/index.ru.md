# zig-tarantool

zig-tarantool позволяет писать код для Tarantool на Zig: хранимые процедуры и
Lua-модули, которые работают внутри процесса Tarantool, и программы, которые
обращаются к Tarantool по сети.

> **Предварительная версия.** У пакета ещё нет версий: подключайте его по
> коммиту и будьте готовы к тому, что API между коммитами меняется.

## Что он умеет

- **Хранимые процедуры на Zig.** Обычная функция Zig становится функцией
  Tarantool с `language = 'C'`. Её аргументы декодируются из MessagePack по
  типам параметров, результат кодируется обратно, а возвращённая ошибка Zig
  завершает вызов ошибкой.
- **API box на Zig.** Спейсы, индексы, кортежи, транзакции, последовательности,
  файберы, каналы, триггеры, decimal и журнал — типизированно и с явными
  временами жизни, поверх C API Tarantool (`module.h`).
- **Lua-модули на Zig.** Структура из функций Zig становится модулем, который
  загружается через `require()`; значения Lua преобразуются в типы Zig и
  обратно.
- **Сетевой клиент.** Коннектор iproto для программ вне Tarantool: CRUD,
  вызовы функций, конвейерные пакеты запросов, схема, watchers и интерактивные
  транзакции. Он работает поверх любого `std.Io`, в том числе такого, при
  котором хранимая процедура на время ожидания сети уступает свой файбер.

## Попробовать

Хранимая процедура:

```zig
const t = @import("tarantool");

fn add(a: i64, b: i64) i64 {
    return a + b;
}

comptime {
    t.proc.exportProc("add", add);
}
```

собранная в `hello.so` и вызванная из Tarantool:

```lua
box.schema.func.create('hello.add', { language = 'C' })
box.func['hello.add']:call({ 1, 2 }) -- 3
```

[Первый модуль](get-started/first-module.md) проходит этот путь целиком, от
пустого каталога до вызова.
